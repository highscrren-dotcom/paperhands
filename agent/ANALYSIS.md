## 1. Цель проекта своими словами

`paperhands` — это **инфраструктура для честного эксперимента**, а не генератор
прибыли. Тезис первоисточника: у LLM-агента сверхчеловеческое распознавание
паттернов, но «нет рук» — в цикле TradingView (Pine → бэктест ≤5000 баров → CSV →
в чат → правка одной строки → повтор) узкое место — человек, а побочный риск —
look-ahead bias из-за передачи «не того файла». Решение — дать агенту локальный
движок, где (а) итерация не упирается в ручной труд человека и (б) агент
**физически не может** подсмотреть будущее или незаметно нарисовать красивую
кривую.

Ключевая ценность, которую мы наследуем, — не «стратегия, которая зарабатывает»,
а **среда, в которой цифре бэктеста можно верить**: нет look-ahead, комиссии и
просадка всегда на виду, есть benchmark `buy & hold`, один и тот же код во всех
режимах. Всё остальное (сами стратегии) — заведомо подозрительно, пока не
подтверждено out-of-sample/форвардом.

## 2. Пять опор из статьи → что говорит автор → что у нас

### Опора 1. Локальный self-hosted Pine (PineTS)
**Автор:** запускать Pine локально ([PineTS](https://github.com/QuantForgeOrg/PineTS),
пакет `@backtest-kit/pinets`), чтобы уйти от веб-редактора TradingView и его лимита
~5000 баров. В `backtest-kit` Pine — часть edit-zone (`math/*.pine`) с правилами
против look-ahead.

**У нас:** Pine нет вообще; стратегии — чистый TypeScript
([src/strategies/](src/strategies/)). Важно понять, что из четырёх причин автора
держаться за Pine мы уже закрыли три другим способом: локальный запуск — есть
(`npm start`), лимита на бары нет, а язык «в датасете LLM» — TypeScript
представлен в обучающих данных не хуже Pine (это же прямо отмечает ветка про
trendspider — см. §3). Единственное, чего мы лишены, — **совместимость с уже
написанными Pine-стратегиями**. Вывод: это **осознанная дивергенция, а не долг**;
PineTS-адаптер имеет смысл только если появится задача импортировать чужой Pine.
Приоритет низкий.

### Опора 2. Временная синхронизация вне редактируемого LLM-кода
**Автор** (статья 979116): часы живут в инфраструктуре, не в стратегии. В
`backtest-kit` это `ExecutionContextService` — обёртка над `AsyncLocalStorage`,
прокидывающая `{ symbol, when, backtest }` во все async-вызовы; загрузчик
`ClientExchange.getCandles()` сам читает контекст и **физически обрезает будущее**.
Загрузчик и часы лежат внутри npm-пакета — агент их не редактирует. Прямая
формулировка автора в комментариях: *«Claude запрограммирован халявить: если можно
обмануть и написать backtest, который подсматривает свечи из будущего, он
целенаправленно так сделает»* → поэтому код загрузки — в `node_modules`.

**У нас:** тот же приём — `clock` (`AsyncLocalStorage`) в
[src/engine.ts:22](src/engine.ts#L22), стратегия видит мир только через
`ctx.series()`/`ctx.now()`, срез идёт по индексу текущего бара
([src/engine.ts:37-45](src/engine.ts#L37-L45)). Для **одного таймфрейма** барьер
корректен. **НО:** наш загрузчик данных лежит в редактируемом репозитории
([src/cli.ts:30](src/cli.ts#L30) `loadFrame`), а файл стратегии технически может
обойти API — `import { readFileSync } from 'node:fs'`, `import '../synthetic'` или
чтение `data/*.jsonl` напрямую. Запрет на это — только текст в `CLAUDE.md`, не
enforcement. Это и есть разрыv из Шага 3(б): **ALS-clock необходим, но не
достаточен** (подробно — §6).

### Опора 3. Один код для backtest/paper/live
**Автор:** одна функция стратегии, режимы различаются источником данных и брокером
(флаг `backtest:boolean`); paper и live **реализованы** (`PaperMainService`,
`LiveMainService`, crash-recovery через `waitForInit`).

**У нас:** архитектурно заложено (одна `Strategy`, LIVE SEAM в
[src/engine.ts:115-132](src/engine.ts#L115-L132)), но paper/live **не
реализованы** — `--mode paper|live` намеренно падает
([src/cli.ts:63-70](src/cli.ts#L63-L70)). Значит разрыва backtest↔paper, о котором
кричит clarkkent5, у нас нет даже возможности пощупать. Ключевой нюанс: чтобы
поймать расхождение уровня clarkkent5, paper/live **не нужен** — достаточно
out-of-sample на истории (см. §6-а).

### Опора 4. JSONL-логи как разметка для LLM
**Автор:** JSONL — нативный формат и для датасета, и для логов; Claude грепает
строку или пишет скрипт для агрегации 50MB логов.

**У нас:** есть, `logs/<runId>.jsonl`, события `meta`/`fill`/`equity`
([src/logger.ts](src/logger.ts), [src/broker.ts:160](src/broker.ts#L160)). Паритет
по сути. У автора богаче (15 persist-адаптеров), но нам это не нужно, пока нет
live. Разрыв незначительный.

### Опора 5. Авто-генерируемый файл Agent Skills
**Автор:** внешний репозиторий `backtest-kit-skills` (`SKILL.md` +
`evals/evals.json` + `references/`), плюс корневой `LLMs.md` (машинная API-спека),
плюс scaffold-`CLAUDE.md` с явными правилами edit-zone. Генератор —
`npx @backtest-kit/sidekick`.

**У нас:** есть `CLAUDE.md` (память/инварианты), но **нет** ни Agent Skill, ни
`evals`, ни авто-генерации. Разрыв есть, но приоритет ниже корректности. Отдельно
ценна идея **evals, проверяющих, что агент не вписал look-ahead** — её стоит
перенять, но позже.

## 4. Разбор PR #31 и урок для нас

**PR #31 «Fix higher timeframe lookahead bias»** (автор фикса — `jesperstarkar`,
смёржен, релиз `backtest-kit@2.3.2`). Суть бага: свеча хранится по времени
**открытия**, а старый фильтр пускал свечу, если `openTime < now`, не проверяя
время **закрытия**. При запросе 1h-свечи в момент 10:24 стратегия получала свечу
10:00, которая внутри себя несёт данные (high/low/close) до 11:00 — **будущее**.
Фикс: в backtest-режиме отдавать только полностью закрытые свечи
(`openTime + interval <= now`). Дополнительно вскрылся спор о конвенции границы:
Binance — exclusive, CCXT — inclusive; мейнтейнер выбрал **inclusive** и переписал
`ClientExchange.getCandles` через выравнивание по границе интервала
(`alignedWhen = floor(when/step)*step`).

**Урок для paperhands.** Мы — одно-таймфреймовый движок, `request.security`-костыля
у нас нет, и на одном ТФ `series()` корректен (решение на close(i), fill на
open(i+1)). Но это **будущая дыра**: если агент (или мы) добавит мультитаймфрейм
или ресемплинг младших баров в старший «на лету», ровно эта ловушка воспроизведётся
— наивная агрегация отдаст незакрытую старшую свечу. Значит в план надо заложить:
(1) регрессионный тест на look-ahead по образцу `test/spec/lookahead.test.mjs`;
(2) если появляется MTF/ресемплинг — инвариант «видима только полностью закрытая
старшая свеча» + явно зафиксированную конвенцию границы (мы — единый ТФ, но правило
надо записать до, а не после).

## 5. Что есть у backtest-kit, чего нет у нас (для контекста gap)

Богатая модель позиции (всё внутри пакета, вне edit-zone):
`scheduled/limit-входы`, `DCA` с гвардом cost-basis (`commitAverageBuy`),
**partial-close** (`commitPartialProfit/Loss`), **breakeven** (`commitBreakeven` —
двигает SL в вход, когда прибыль перекрыла fees+slippage), **trailing**
(`commitTrailingStop/Take`), **timeout** (`time_expired`, поле
`minuteEstimatedTime`), **partial-fill** лимитника в live
(`createLimitOrderAndWait`). Комиссия+слиппедж моделируются направленно
(`toProfitLossDto.ts`); **funding и спред в PnL — НЕ моделируются** (как и у нас —
это общая честная граница, а не только наш пробел). Риск — отдельный слой с
портфельным резервированием (`checkSignalAndReserve`).

У нас сигнал плоский: `long/short/close/hold` + `stopLoss/takeProfit/sizePct`
([src/types.ts:21-31](src/types.ts#L21-L31)); брокер — SL/TP по диапазону бара,
all-or-nothing закрытие, стоп при двойном срабатывании считается первым
([src/broker.ts:108-130](src/broker.ts#L108-L130)).

## 6. Ответы на три вопроса Шага 3

### (а) Чем закрываем разрыв backtest↔paper, которого нет вообще
Разрыв закрывается в **два независимых хода**, и первый не требует ни paper, ни
live, ни биржи:

1. **Out-of-sample / walk-forward на истории (Phase 1).** Расхождение уровня
   clarkkent5 — это переобучение. Его видно **на исторических данных**: делим
   ряд на in-sample/out-of-sample (или скользящим окном walk-forward), считаем
   деградацию метрик (return/Sharpe in vs out). Если стратегия рушится на
   held-out периоде — мы поймали clarkkent5, не потратив двух недель paper.
2. **Paper как ступень перед live (позже).** Paper (live-цена, без реальных
   ордеров) на том же движке ловит расхождение уже в реальном форвард-времени и
   проверяет предположения об исполнении/задержках. Это дополняет, а не заменяет
   п.1.

Вывод: сначала дешёвый OOS-детектор (Phase 1), только потом paper (после того как
цифрам бэктеста вообще можно доверять).

### (б) Достаточно ли ALS-clock, или data-layer тоже выносить из зоны агента
**Недостаточно.** ALS-clock гарантирует, что *штатный API* (`ctx.series()`,
`ctx.now()`) не видит будущего. Он **не** мешает стратегии обойти API вообще:
`import 'node:fs'` и прочитать `data/*.jsonl`, `import '../synthetic'` и
перегенерить весь ряд, или дотянуться до внутренностей движка. Сейчас это
запрещено только текстом в `CLAUDE.md`. `backtest-kit` закрывает это физически —
загрузчик в `node_modules`. Нам нужен **enforcement**: статический guard (проверка
импортов в `src/strategies/**` по allowlist `../types`, `../indicators`),
падающий в typecheck/CI, плюс регрессионный тест на look-ahead. То есть да —
data-layer должен уйти из досягаемости агента не документацией, а проверкой.

### (в) partial fill / breakeven / таймаут позиции — «не держать актив часами»
У нас нет ни одного из трёх. Разложим по ценности и сложности:

- **Position timeout (макс. время удержания)** — прямое воплощение тезиса «не
  держать актив часами»: закрыть позицию через N баров с причиной `time_expired`.
  Самое ценное и самое простое. **Высокий приоритет** (но после Phase 1).
- **Breakeven** (перенести SL в вход, когда прибыль перекрыла fees+slippage) —
  снижает give-back. Средний приоритет.
- **Partial close** (зафиксировать часть на уровне, остальное пусть бежит) — тот
  самый пример «спайк дал 90% прибыли выходом частями». Средний приоритет.
- **Partial FILL** (ожидание налива лимитника) — это **live-only** концепт, к
  backtest неприменим; трогаем только на этапе live.

Важно: обогащать модель позиции имеет смысл **только после** валидатора (Phase 1).
Нет смысла добавлять таймаут/breakeven, пока мы не умеем отличать реальный эффект
от переобучения.

## 8. Инварианты, которые план обязан сохранить

1. Look-ahead-барьер абсолютен: стратегия видит рынок только через
   `ctx.series()`/`ctx.now()`; любая правка, дающая ей прямой доступ к данным/часам
   — стоп и флаг владельцу.
2. Один код для backtest/paper/live — не плодить «live-версию» стратегии.
3. Комиссии/фрикшн и просадка всегда на виду; всегда benchmark `buy & hold`.
4. Логи — JSONL, объект на строку.
5. Порядок backtest → paper → live; live не предлагать раньше времени.
6. Evidence-first: к цифрам бэктеста относимся скептически, пока не подтверждены
   форвардом/OOS; прибыльность не обещаем.
