> Подготовлено 2026-07-08 по просьбе автора («интересен фидбек по анализу
> новостной ленты с tavily.com, взамен буду консультировать»). База: код
> `example/logic/` (feb_2026, backtest-kit 15.2.0), три multi-day/интрадей
> paper-прогона BTCUSDT (5ч + 8.5ч + текущий), прямые пробы Tavily API на

## Что понравилось (проверено по коду и прогонам)

1. **Дата-гигиена настоящая.** `fetchNews` отбрасывает статьи без
   `publishedDate` И статьи с «полуночной» датой (00:00 = дата без времени),
   окно жёстко `[when−24h, when]`. Для контраста: в trading-agents-docker
   DDGS-путь статьи с непарсящейся датой ОСТАВЛЯЕТ (`except: pass`) — там
   look-ahead течёт, здесь нет. Это правильная сторона баррикады.
2. **Осознанный аллоулист доменов** с комментарием ПОЧЕМУ исключены
   coindesk/reuters/bloomberg (нет даты публикации) — редкий случай, когда
   фильтр данных документирует сам себя. Плюс sanity-гард на пересечение
   allow/disallow списков.
3. **Кэш по дневной свече в backtest** (`Cache.file interval 1d`, ключ
   symbol_topic_alignMs_query) — воспроизводимость и стоимость под контролем;
   live без кэша — честно отражает момент.
4. **Промпт форекаста** — чистая 4-позиционная шкала + reliable/not_reliable +
   обязательный reasoning; «слабый поток — тоже информация» — грамотно.

## Главная находка: пайплайн структурно голодает (цифры)

За ВСЕ наши paper-прогоны `fetchNews … len=0` — всегда. Ноль сделок не потому,
что сентимент нейтрален, а потому что **вход пустой**. Прямые пробы API
(та же дата-выборка 2 дня, те же параметры search):

| конфигурация | результатов | score-диапазон | проходят порог >0.68 |
|---|---:|---|---:|
| авторский запрос + аллоулист | 2 | 0.07–0.31 | **0** |
| «Bitcoin» + аллоулист | 2 | 0.05–0.29 | **0** |
| «Bitcoin price news» + аллоулист | 2 | 0.08–0.55 | **0** |
| «Bitcoin price news» БЕЗ аллоулиста | 14 | до 0.78 | 3 |

Вывод: **аллоулист и порог 0.68 несовместимы**. На доменах из аллоулиста
Tavily-скоры почти никогда не достигают 0.68 (максимум, что мы видели, — 0.55),
т.е. фильтр «relevance > 0.68» при включённом `includeDomains` == «выбросить
всё». Дальше цепочка: пустой контекст → LLM честно отвечает
neutral/not_reliable → getSignal null → стратегия не торгует никогда.

## Рекомендации (по убыванию важности)

1. **Калибровать порог под аллоулист**: при `includeDomains` скоры смещены
   вниз — порог ~0.35–0.45 (или перцентиль выдачи, напр. top-50% по score)
   вместо 0.68. Либо убрать аллоулист и фильтровать домены постфактум,
   сохранив порог.
2. **Guard на пустой вход**: если `len=0` — не звать LLM вообще (экономия
   токенов/латентности) и логировать/дампить явный вердикт `no_data` вместо
   неотличимого от «сбалансированного фона» neutral. Сейчас «нет данных» и
   «нейтральный рынок» — одно и то же состояние, это ломает интерпретацию
   paper-статистики.
3. **Шаблонизировать запрос по символу**: `TOPIC_QUERIES` захардкожен
   «Bitcoin …», хотя `symbol` в advisor приходит и `DISPLAY_NAME_MAP` уже
   существует в outline. На ETHUSDT стратегия будет торговать по биткойн-новостям.
4. **Запрос-инструкция → топиковые запросы**: «Bitcoin market sentiment. Can
   be bullish, bearish, neutral or sideways» — это промпт для LLM, а не
   поисковый запрос; семантический поиск матчит слова про «sentiment», а не
   новости. Простой «Bitcoin price news» дал скоры выше (0.55 vs 0.31 на
   аллоулисте, 0.78 vs — без него). Инструкция про bullish/bearish уместна
   в FORECAST_PROMPT (где она уже есть), не в query.
5. **Второй топик с негативным смещением**: рынок асимметричен к плохим
   новостям; отдельный запрос вида «Bitcoin regulation lawsuit hack» повышает
   отзыв на события, которые реально двигают цену (у вас же в
   trading-agents-docker эта идея негативных запросов уже была — сюда она
   просится ещё больше).
6. **Инженерное, не про Tavily**: необработанный ccxt `RequestTimeout`
   (binance klines, 10s) убивает весь paper-процесс — наблюдали дважды на
   multi-day прогонах. Ретрай/backoff в ccxt-адаптере или хотя бы
   рекомендация супервизора в доке. И туда же: `--paper` при рестарте
   флашит dump/ — для multi-day paper под супервизором обязателен
   `--noFlush`, иначе каждая авария стирает накопленную статистику.
