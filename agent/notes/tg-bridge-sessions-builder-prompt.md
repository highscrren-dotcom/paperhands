## Задача

Красивое управление сессиями Claude из телеги: список существующих сессий с
человеческими ярлыками, переключение тапом по инлайн-кнопке, переименование.
Мост уже умеет /new /sid /ping и хранит текущий session_id в state.json —
это расширяем, не ломая.

## Факты (проверено главной сессией — не перепроверять, но СВЕРИТЬ при правке)

- Сессии проекта: `/home/s1dd1/.claude/projects/-home-s1dd1-dev-quant/*.jsonl`,
  имя файла = `<session_id>.jsonl`. Директория = escape(cwd моста
  /home/s1dd1/dev/quant): слеши→дефисы, ведущий дефис. Вычислять из CFG.cwd,
  не хардкодить (сменится cwd — путь поедет).
- **Ярлык сессии** = текст ПЕРВОЙ строки jsonl, где `type==="user"` И
  `typeof message.content === "string"` (массивы content = tool-результаты/
  вложения, ПРОПУСКАТЬ). trim, ≤40 симв. Нет такой строки → ярлык
  «(без текста)». Пример: db02f9d3 → «Что записано в DECISIONS №96?».
- Число сообщений (для показа) = count строк `type==="user"` со строковым
  content. mtime файла = свежесть + детект активности.
- bridge.mjs читает jsonl НАПРЯМУЮ через node:fs (не через claude-child) —
  deny-профиль тут ни при чём, доступ полный. НЕ делать это через claude -p.

## Реализация

### 1. Обзор сессий (bridge.mjs, чистые функции — в lib.mjs под тесты)
`listSessions()` → массив `{sid, label, msgs, mtimeMs, active, current}`,
сортировка по mtimeMs убыв. `label` — из registry (custom /name), иначе
авто-извлечение выше. `current` = sid===state.session_id. **active** = mtime
моложе 120с (защита: главная IDE-сессия и работающий строитель пишут файл
постоянно — их mtime свежий). Читать jsonl построчно, не грузить целиком в
память (файлы до нескольких МБ — достаточно найти первую user-строку и
посчитать; можно ограничить чтение первыми N КБ для ярлыка + быстрый wc).

### 2. Реестр ярлыков `sessions.json` (в корне моста, В .gitignore как state)
`{ "<sid>": {"label": "текст"} }` — оверлей человеческих имён поверх авто.
`/name <текст>` пишет label текущей сессии. Формат как state.json.

### 3. Инлайн-кнопки + callback_query
- В getUpdates добавить `'callback_query'` к allowed_updates (сейчас только
  `'message'`). Рубеж classifyUpdate расширить: callback от чужого from.id →
  drop+audit, как чужие сообщения.
- `/sessions` (алиас `/ls`): текст-список (● текущая, 🔒 active) + reply_markup
  inline_keyboard, по кнопке на сессию, callback_data=`use:<sid>`
  (36+4=40 байт < лимита 64). Кнопка активной — с 🔒 в тексте.
- Обработка callback: **ВСЕГДА answerCallbackQuery** (иначе у клиента вечный
  спиннер). Если sid active → answerCallbackQuery с alert «сессия активна,
  резюмить нельзя (2 процесса × 1 файл = порча)», НЕ переключать. Если sid
  больше не существует (файл удалён) → «сессии нет». Иначе: state.session_id
  = sid, saveState, answerCallbackQuery «переключился», и editMessageText/
  reply с подтверждением ярлыка.
- Текстовый фолбэк `/use <sid|N>` оставить (кнопки могут не прийти; N = номер
  из последнего /sessions — хранить последний показанный порядок в памяти
  процесса). Та же защита active.

### 4. Мелочи
- `/ping` дополнить текущим ярлыком. `/new [ярлык]` — при наличии текста сразу
  писать label будущей сессии (sid узнаешь после первого прогона — отложенная
  запись: запомни pending-label, привяжи к новому sid в processOne).
- `/start`-справку обновить: /sessions, /use, /name.

## Безопасность (НЕ ослаблять — иначе приёмка не пройдёт)

1. **Ярлыки идут через redact() перед отправкой** — jsonl-контент сессий может
   содержать секреты (значения из логов/выводов); первое user-сообщение обычно
   чистое, но редакция обязательна на весь текст /sessions. Проверить фактом.
2. callback_query.from.id === ALLOWED_CHAT_ID — тот же гейт, что у сообщений;
   чужое → drop+audit (подделать from.id нельзя, но проверка обязательна).
3. setWebhook НЕ вызывать. Токен по-прежнему из боевого .env, не хранить.
4. deny-профиль settings.claude.json НЕ трогать (самозащита моста цела).
5. Реестр sessions.json — в .gitignore (может содержать ярлык-текст сессий).

## Чеклист приёмки (выполнит главная сессия)

1. /sessions → список с кнопками; текущая ●, наша активная IDE-сессия 🔒;
2. тап по завершённой сессии моста → переключение + подтверждение; audit
   пишет callback с from.id;
3. тап по 🔒-активной → отказ алертом, переключения нет;
4. /name сделки → ярлык текущей сменился, виден в /sessions и /ping;
5. resume после переключения: перешёл на сессию X → вопрос по её теме →
   вспоминает (контекст той сессии);
6. /use N (текст-фолбэк) переключает так же; /use по активной — отказ;
7. подделка callback с чужим from.id → drop+audit, без переключения;
8. секрет в ярлыке (подложить сессию с токеном в первом сообщении) →
   заредактирован в выводе;
9. allowed_updates = только message+callback_query; getWebhookInfo пуст;
10. фаза 1 не сломана: /ping, обычный текст, deny (systemctl→отказ) работают.
