## UX (ядро ТЗ)

1. **/start** → приветствие + inline-кнопка «▶️ Старт» (для первого касания);
   по нажатию — постоянное reply-меню (клавиатура) с кнопками, дублирующими
   команды. Кнопка меню = команда: обработчик один.
2. **setMyCommands при старте бота** — команды появляются в подсказке
   Telegram при вводе «/» (это и есть «дублировались команды введя слеш»).
3. Ответы — чистые, с эмодзи-статусами (✅/🔴), моноширинными блоками для
   цифр, БЕЗ простыней: каждая команда ≤ 15 строк.

## Команды (все read-only!)

- /status — контур: процессы live/paper (pgrep), свежесть тиков (live-ingest
  и live.jsonl feb), вотчдоги, mtime кронов forward/volume, ОЗУ; формат
  «✅ всё зелёное» или список красного;
- /balance — Binance read-only (fetchBalance по ключам из
  backtest-ollama-crontab/.env через dotenv path): USDT free + не-USDT активы
  >$5 с пометкой «СИРОТА?» если signal-items пуст (урок №88);
- /signals — последние 3 parser-items из mongo backtest-pro (read-only!) с
  вердиктом гейта из screen-items (follow/skip + причина кратко);
- /news — fit-gate из хвоста news-cron.log + счётчики news-audit (ok/total)
  + mtime лога;
- /service — health news-service (127.0.0.1:8080/api/v1/health) + journal/stats;
- /help — список команд.

## Ограничения (жёсткие)

- ТОЛЬКО ЧТЕНИЕ: никаких торговых команд, никаких рестартов, никакого
  createOrder — бот-пульт наблюдения, не управления (телефон могут увести).
- Доступ: whitelist по chat_id владельца (env TG_ALLOWED_CHAT_ID; на первый
  /start без настройки — показать chat_id и попросить владельца вписать).
- Боевые процессы/базы не трогать: mongo read-only, ключи Binance читаются
  из чужого .env только для fetchBalance.
- Запуск: systemd-юнит через systemd-run --user (строку дать владельцу) +
  строка @reboot в crontab (дать, ставит владелец). Переживает VSCode (№49).
- Минимум зависимостей; новый репо git init, коммиты/github — решение
  владельца; токен в .env (chmod 600, .gitignore), не светить в логах.
- Ничего не коммитить в paperhands без «комить».
