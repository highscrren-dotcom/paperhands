Задача — скрипт-каркас `example/scripts/news_dataset/news_sharpe.mjs`:
валидация вердиктов классификатора ПОСЛЕДУЮЩИМ движением цены, метрика — Sharpe
по ячейкам heatmap. Сейчас данных мало (items≈8) — строим КАРКАС с честной
плашкой малой выборки; ценность вырастет с накоплением.

## Методика

1. Берём ok-вердикты из mongo `news-audit` (через логику news_query: status ok,
   одна promptVersion, backfill исключён по умолчанию — флагом можно включить
   с оговоркой в выводе).
2. Для каждого: 1m-свечи ПОСЛЕ publishedAt (fast_candles), горизонты
   1h / 4h / 24h. Направленная доходность: long → (close_h/entry−1), short →
   (entry/close_h−1); entry = close первой минуты ПОСЛЕ publishedAt (никакого
   look-ahead; фрикшн НЕ вычитаем — это валидация прогноза, не стратегия,
   но напечатать напоминание про 0.2% фрикшна в шапке).
3. Heatmap: строки = домен (псевдо-канал), колонки = event_type × горизонт.
   В ячейке: n, mean, std, **Sharpe = mean/std** (по-сделочный, без
   аннуализации — как «>1.0» у автора), плюс отдельная сводка по confidence-бакетам
   (0.3/0.6/0.9) — проверить, коррелирует ли LLM-уверенность с исходом
   (гипотеза автора: нет).
4. Вывод: markdown-таблица в stdout + файл agent/notes/news-dataset/sharpe-heatmap.md
   (перезаписывается, в шапке дата+promptVersion+n). Ячейки с n<5 помечать
   «н/д» — Sharpe на 1-2 точках не печатать числом (иначе соблазн поверить).

## Ограничения

- Mongo backtest-pro не трогать; news-audit — только чтение.
- Свечи — fast_candles (кэш), Binance не долбить: горизонты батчами.
- Tavily/Ollama не вызывать вообще.
- Боевой конвейер не трогать; новый скрипт — отдельный, в крон НЕ ставить
  (запуск руками/дежурством после накопления).
- Ничего не коммитить без «комить».
