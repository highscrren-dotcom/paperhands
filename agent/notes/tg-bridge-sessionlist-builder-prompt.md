# Промпт строителю: tg-claude-bridge — порядок и вид списка сессий (фаза 4)

Продолжение `/home/s1dd1/dev/quant/tg-claude-bridge/` (фазы 1-3 приняты главной
сессией 18.07; репо highscrren-dotcom/backtest-claude-telegram НЕ запушен — пуш
после приёмки этой фазы). Читай README.md, bridge.mjs, lib.mjs, sessions.mjs
целиком. Владелец, глядя на живой /sessions, дал 3 правки — все про то, чтобы
список был читаемым и предсказуемым. Ниже — решения владельца, НЕ переголосовывать.

## Проблема (диагностирована главной сессией фактом)

Сейчас сорт строго по mtime ФАЙЛА. Но mtime расходится с реальным разговором:
у транзитных сессий (одноразовые пробы) mtime на 15-22 мин НОВЕЕ последнего
сообщения (файл кто-то тронул позже) — поэтому пустышки всплывают ВЫШЕ
настоящих сессий. Плюс авто-ярлык = первое user-сообщение часто ловит шум
(`<task-notification>`, служебные строки, текст проб) — «не читаемо». Плюс
грубое «~3ч» у многих — порядок глазу не виден.

## Что сделать (3 решения владельца)

### 1. Сортировка по ВРЕМЕНИ ПОСЛЕДНЕГО СООБЩЕНИЯ (не mtime файла)
Ключ сортировки (убыв.) = timestamp последней содержательной строки jsonl
(поле `timestamp` в строке; берём последнюю непустую строку с этим полем).
Фолбэк, если ни в одной строке нет timestamp → mtime файла. Так настоящий
разговор поднимается над транзитными пробами.
- ВАЖНО: mtime всё равно нужен — но ТОЛЬКО для детекта активной (🔒 mtime<120с,
  файл пишется прямо сейчас). Активность и сорт-ключ теперь РАЗНЫЕ поля.
- Эффективность: файлы до ~3 МБ (главная сессия). Последний timestamp читать
  с КОНЦА (последние ~16 КБ, разбить на строки, взять последнюю с timestamp),
  НЕ грузить весь файл. msgCount и метаданные — как раньше, потоково; кэш по
  mtime оставить (инвалидация по mtime корректна и для контент-времени, т.к.
  новое сообщение двигает и mtime).

### 2. Скрывать пустые и короткие сессии
Показывать сессию, только если `msgCount >= 3` (user-сообщений со строковым
content). ИСКЛЮЧЕНИЯ — показывать ВСЕГДА, даже если короткая: текущая
(state.session_id) и та, у кого есть custom-ярлык в реестре (/name). Скрытые
НЕ удаляются — `/use <sid|префикс>` находит любую. Внизу списка строка-счётчик:
«+N скрытых (короткие/пустые) — /use <sid> найдёт любую».

### 3. Ярлык = имя, БЕЗ мусорного первого сообщения
Больше НЕ извлекать первое user-сообщение как заголовок (владелец: «названия
не читаемые, оставить имя сессии»). Приоритет отображаемого имени:
1. custom-ярлык из реестра (/name) — если задан;
2. иначе — короткий session_id (первые 8 симв., напр. `db02f9d3`).
Строку сессии собрать читаемо: `<имя> · <время> · <N сообщ>`, текущая с ●,
активная с 🔒. Функцию авто-извлечения первого сообщения можно удалить или
оставить мёртвой — на выбор, но в списке она не участвует.

### 4. Читаемое время (мелочь, чтоб порядок был виден глазу)
Вместо грубого «3ч» — абсолютное: если сегодня → `HH:MM`, иначе → `DD.MM HH:MM`
(локальное время машины). Тогда сортировка видна.

## Инварианты (НЕ ослаблять)
1. Ярлык (custom /name) по-прежнему через redact перед отправкой — /name может
   содержать секрет. sid редактировать не нужно (это не секрет), но общий
   проход redact на весь текст /sessions оставить.
2. callback_data=use:<sid> и гейт from.id, answerCallbackQuery, защита active
   (🔒) — как в фазе 2, не трогать. setWebhook нет. deny-профиль не трогать.
3. Скрытие — только визуальное; /use по sid/префиксу достаёт скрытую.
4. Номера /use N нумеруют ВИДИМЫЙ список (после фильтра), консистентно с показом.

## Чеклист приёмки (главная сессия)
1. /sessions: верхняя — с самым свежим ПОСЛЕДНИМ сообщением (не mtime); проверю
   сверкой с парсингом последнего timestamp jsonl;
2. транзитные пробы (короткие) скрыты; счётчик «+N скрытых» верен;
3. текущая сессия показана даже если короткая (● на месте);
4. /name proba → названная сессия показана даже короткой, ярлык виден;
5. ярлык без custom = короткий sid, БЕЗ текста первого сообщения; мусорных
   «<task-notification>…» в списке нет;
6. время читаемое (HH:MM сегодня / DD.MM иначе);
7. /use <sid скрытой> переключает (скрытие визуальное); /use N по видимым;
8. фазы 1-3 целы: deny, tap-переключение, 🔒-active, redact ярлыка /name,
   меню/слеш-команды; node --test зелёные;
9. скан секретов диффа.
