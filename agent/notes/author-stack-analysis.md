# Три репозитория: движок и два источника сигналов — честный разбор

Все ключевые утверждения проверены по коду обоих форков (не по описанию). Расхождений с реальностью не нашёл; отдельные оговорки помечены ниже. Решения, которые не мои — помечены **🚩 РЕШЕНИЕ ВЛАДЕЛЬЦА**.

## A. Что это — по одному абзацу

**1. Движок (хребет): paperhands / backtest-kit.** Единственный слой исполнения. Владеет look-ahead-безопасными данными и часами (`AsyncLocalStorage`-контекст, полу-открытое окно свечей, pending-свеча исключена), моделирует комиссию 0.1% + слиппедж 0.1% (funding и спред НЕ моделирует), держит жизненный цикл сигнала, валидацию, единый харнесс backtest→paper→live и брокер-адаптер. Владеет `getSignal`, схемами frame/exchange и CLI. Ни один из двух других репозиториев не исполняет сделки и не касается брокера.

**2. Источник сигналов A: pump-anomaly** (npm TS-библиотека, чистая и без сети). Превращает поток рекомендаций из Telegram-каналов (`ParserItem[]`) в готовый план сделки: `PumpMatrix.load(model.json).plan(items, getCandles)` → `TradeSignal` c полями `{symbol, direction (уже инвертирован, если сработал каскад), entryFromPrice/entryToPrice, exit}`. Проверено по `src/signal.ts` и `src/pump-matrix.ts:236-271`. Ключевое: **`exit` — это трейлинг + peak-staleness в ПРОЦЕНТАХ (`trailingTake`, `hardStop`, `impactHorizonMinutes`, `stalenessSince*`), а не фиксированный `priceTakeProfit`.** Поля `priceTakeProfit` в выводе нет вообще.

**3. Источник сигналов B: trading-agents-docker** (Python FastAPI-сайдкар). Мульти-агентный LLM-анализ поверх ccxt / DuckDuckGo / stockstats; `POST /api/v1/propagate {company_name, trade_date}` → рейтинг `BUY|OVERWEIGHT|HOLD|UNDERWEIGHT|SELL` плюс полные тексты рассуждений. Проверено: в рабочем графе включены только аналитики `["social","news"]` (`main.py:58`) — **технический/market-аналитик выключен**, fundamentals заглушён. То есть это, по сути, тяжёлый news-sentiment движок, а не богаче feb_2026, а дороже.

## B. Как они складываются в стек

Один хребет + два сменных источника. Поток данных:

**Pump-путь:**
```
Telegram-каналы → [парсер владельца, НЕ входит ни в один репо] → ParserItem[]
  → pump-anomaly plan(items, ДВИЖКОВЫЙ getCandles)
  → {direction, зона входа, exit-%}
  → тонкая strategy-обёртка backtest-kit маппит в getSignal:
     {id, position, priceOpen, priceStopLoss, minuteEstimatedTime}
  → движок (look-ahead-гард + fees/slippage) → брокер (paper/live)
```

**Agents-путь:**
```
ccxt/DDG → сайдкар /propagate(company, ambient `when` как trade_date)
  → BUY..SELL → тонкая getSignal маппит рейтинг → позиция + брекет (TP/SL считаем сами, ATR)
  → движок → брокер
```

Стабильный шов — два контракта, которые автор держит идентичными во всех репо: **семантика диапазона `getCandles`** (у pump-anomaly `entryStartTs`/полу-открытое окно совпадает с `ClientExchange` один-в-один) и **форма сигнала/exit**. Это и есть свидетельство, что три репо проектировались как одна система.

**Почему автор указал владельцу именно на pump-anomaly (связь с jan_2026).** jan_2026 («Liquidity Harvesting») — единственная example-стратегия, обыгравшая buy&hold (Sharpe 1.14 по её README). Проверено: это ручной прототип с **одним** каналом (Crypto Yoda), **одним** месяцем, захардкоженными `TRAILING_TAKE=1.0` / `HARD_STOP=1.0` / staleness 240 мин, инверсией через эвристику «4h-midpoint», без author-dedup, без каскад-проверки, без OOS-гейта — ровно тот «красивый одномесячный результат», которому доктрина велит не верить. pump-anomaly — это тот же концепт и те же exit-примитивы (трейлинг/peak-staleness/life-cap теперь работают как обучающий ЛЕЙБЛ через path-aware реплей по 1m-свечам), но каждая слабая точка укреплена: обобщение на много каналов/активов с per-asset грид-конфигами; author-cluster dedup (matrix-режим: отличить реальный приток капитала от одного актора, кукловодящего N анонимными каналами); детект ликвидационного каскада с veto/invert (принципиальная замена ручной инверсии jan_2026); и встроенный слой статистической СЕРТИФИКАЦИИ (Deflated Sharpe, PBO, White/Hansen SPA, nested-CV OOS, meta-ledger family-wise-коррекция за частые рефиты). То есть автор отдаёт владельцу самосертифицирующуюся, анти-оверфит-версию его же лучшей идеи — это по духу сильнее нашего собственного OOS-гейта.

## C. Честный EV и риски (по нашей доктрине)

### pump-anomaly — технически лучший, но это «серая зона» в костюме матбиблиотеки

**Что тут +EV (если эдж реален):** не предсказание фундамента, а микроструктура — (a) прокатиться на импульсе толпы, который создаёт пост, и (b) фейдить его через cascade-invert, когда пост — это приманка, заводящая толпу в плечо перед ликвидационным свипом. Инженерия честная: path-aware лейблы закладывают стоп-ханты (главный анти-оверфит-ход для этого домена), честная реализация `−hardStop%` (был баг, раздувавший RR — исправлен), тензор exit не смешивает matrix/single, long/short и calm/anomalous, и тяжёлый сертификационный стек. Это правильный скептический инструментарий.

**Хрупкое ядро (реальная зависимость):** живой **Telegram-signal-feed**. Библиотека его НЕ производит — `types.ts:5` прямо говорит, что схема приходит из внешнего `backtest-ollama-crontab` (Telegram-скрейпер + Ollama-парсер на кроне). Реальные зависимости: (1) существование и скрейпинг конкретных платных/приватных каналов; (2) точный и своевременный LLM-парс свободного текста в `{symbol, direction, зона}`; (3) достаточная стационарность поведения каналов, чтобы недельный рефит успевал. В matrix-режиме нужно ≥2 действительно независимых автора на один тикер — на одноканальном фиде он молча схлопывается в single (каждый пост = вход, качество несёт только exit).

**Footgun-и / серая зона (README не скрывает: «Be aware of meeting the Tax Officers or Telegram channel owner»):**
- Торговля вокруг pump-and-dump-координации: пиггибэк/фронт-раннинг организованного пампа может квалифицироваться как участие в манипулятивной схеме — юридически опасно, зависит от юрисдикции.
- Контрагент по данным — **враждебный**: организатор пампа зарабатывает, сливая на подписчиков; invert/veto пытается снайпить его же ловушку — он может детектить и жечь вас (менять тайминг, постить фейковые зоны, гонять стоп-ханты специально против фейдеров).
- Налоговая/отчётная экспозиция на прибыль.
- Хрупкость фида экзистенциальна: канал ушёл в тень / сменил формат / стал платным / скрейпер молча сломался — фид умирает без рыночного сигнала, что что-то не так.
- **Архитектурный разрыv с нашей доктриной:** exit — трейлинг + peak-staleness, а не фиксированный `priceTakeProfit`. Честный маппинг (вариант b) требует, чтобы стратегия держала состояние между свечами и гоняла трейлинг на каждом закрытии свечи (`listen*Ping`) — а текущая доктрина «тонкой обёртки» (pine считает фиксированные TP/SL) этого не позволяет. Синтез статического TP из трейлинг-% (вариант a) теряет эдж и может нарушить min-TP-1%/RR≥2 (часть гридов разрешает sub-1% `hardStop`/`trailingTake`, которые съест фрикшн + немоделируемый funding/спред мем-коинов).

**Вердикт EV:** потенциально +EV на микроструктуре, но это на 80% проблема ДОБЫЧИ ДАННЫХ и ЛЕГАЛЬНОСТИ, на 20% — код. Не тащить в live быстро. Использовать как (a) исследовательский стенд для проверки cascade-invert-тезиса на исторических parser-items через наш OOS/walk-forward гейт и (b) требовать явного решения по юр/налоговой позиции до paper→live, плюс haircut EV на спред/funding.

### trading-agents-docker — мощно, но медленно, дорого-по-латентности и недетерминированно

**+EV-часть:** структурированное bull/bear + risk-committee-рассуждение как источник направления и как логируемый rationale в live.

**Footgun-и (проверено по коду):**
- **Look-ahead-протечка в news-пути (критично для backtest):** `DDGS().news()` — это живой веб-поиск «сейчас», запрос вшивает человеческий месяц («BITCOIN news January 2026»). Фильтр по дате есть, НО если у статьи нет парсящегося поля `date` — она **остаётся** (`if pub_date_str:` пропускает фильтр; `except ValueError: pass` → тоже оставляет). `get_global_news` дату игнорирует вовсе. Значит `/propagate` не воспроизводим и может протащить будущий/переписанный нарратив. **Проваливает наш абсолютный look-ahead-инвариант на стадии backtest.** Цена-путь (ccxt, отсечка `< trade_date`) при этом дневной и относительно чистый — но market-аналитик всё равно выключен.
- **Латентность:** каждый `/propagate` = 12–20 последовательных LLM-вызовов (аналитики с tool-calling → bull/bear → research-judge → trader → 3 risk-голоса → risk-judge). На Ollama Cloud deep-think это десятки секунд–минуты. Пер-бар в backtest не вызвать; максимум раз в день.
- **Стоимость:** при штатном `.env` (Ollama Cloud, тот же план, что у feb_2026) — почти ноль $ маржинально, но тяжёлая токен/латентность-нагрузка. Если кто-то переключит `LLM_PROVIDER` на OpenAI/Anthropic gpt-5-class (как намекает README-таблица) — ~$0.1–$1+ за вызов, месячный дневной backtest = десятки долларов за один невоспроизводимый прогон.
- **Недетерминизм:** LLM-семплинг + живой DDG → два прогона одной `trade_date` расходятся. Ломает наш OOS/walk-forward гейт (он ждёт воспроизводимых сигналов). Сида/кэша нет.
- **Не даёт уровней/сайзинга:** только направление. Сам по себе наш signal-контракт не закрывает.

**Вердикт EV:** тот же эдж, что у feb_2026 (crypto news/social sentiment → направление), но в 10–20× вызовов и латентности, с выключенным техническим аналитиком. Для backtest — не проходит гейт. Держать как **paper/live advisor** (`trade_date = today`), не как backtest-источник. Дешевле — оставить одно-вызовный `forecast()` feb_2026 и при желании позаимствовать оттуда только идею negative-biased-запросов и `process_signal` 5-way классификатор, не таща весь мульти-агентный стек.

## D. Структурирование (кратко)

**Три отдельных сиблинг-форка, не монорепо** — чтобы каждый оставался ребейзабельным на своём upstream (наши правки только в `agent/` + проектный слой, ядро не трогаем).

- **paperhands/backtest-kit** — интеграционный хаб; только здесь живут стратегии. Всё проводится тут.
- **pump-anomaly** — как version-pinned npm-зависимость стратегии (пин по аналогии с `backtest-kit@14.1.0`). Стратегия импортирует `PumpMatrix`, грузит `model.json`, зовёт `plan()` с **движковым** `getCandles`. Локальные правки форка до апстрима — через `npm link`. Исходники НЕ вендорить.
- **trading-agents-docker** — как сайдкар-сервис (`docker compose up`), никогда не вендорить (Python). Стратегия ходит по HTTP; передавать ambient `when` как `trade_date`.

Замороженный шов через все три: схема `ParserItem`, семантика диапазона `getCandles` (уже идентична) и форма `getSignal`/exit. `model.json` и per-asset гриды — это данные, лежат в директории стратегии рядом с адаптером. Пуш в любой origin — только по явному аппруву.

## E. Рекомендуемая последовательность шагов

1. **🚩 РЕШЕНИЕ ВЛАДЕЛЬЦА (блокирующее для pump-пути):** зафиксировать юридическую/налоговую позицию по торговле вокруг Telegram-pump-сигналов до любого paper→live. Без этого — только исследовательский стенд.
2. **Исследовательский стенд pump-anomaly (без денег):** прогнать `plan()`/`backtest()` на историческом логе parser-items (взять формат `jan_2026/assets/entry.jsonl`, дотегировать полем `channel`), проверить cascade-invert-тезис через наш `agent/tools/oos-gate.mjs` **И** встроенную сертификацию pump-anomaly. Промоутить только при `certified:true` И прохождении нашего гейта (два гейта, не один).
3. **Решить архитектурный разрыв exit:** либо (b) добавить stateful candle-close exit-путь в тонкую стратегию (честно воспроизводит `replayExit`), либо (a) синтез статического TP — но тогда явно проверить, что не нарушается min-TP-1%/RR≥2, и заложить haircut на немоделируемые funding/спред. **🚩 РЕШЕНИЕ ВЛАДЕЛЬЦА:** допустить ли исключение из доктрины «тонкой обёртки» ради (b).
4. **Живой feed — отдельная новая работа владельца:** Telegram-ingest + text→ParserItem парсер с тегом `channel`. Ни один из репо его не даёт. Для backtest — реплей исторического лога; для live — стриминговый парсер как новый компонент.
5. **feb_2026 остаётся текущим paper-субъектом**; trading-agents держать в резерве как paper/live news-advisor (`trade_date=today`), не как backtest-источник. При желании — перенести только `process_signal`-классификатор и negative-query-идею в feb_2026, без всего стека.
6. **Порядок неизменен:** backtest → OOS/walk-forward + сертификация → paper → live (аппрув владельца, малый ~100 USD сайз). pump-anomaly становится ведущим live-КАНДИДАТОМ, но конвейер не сокращает.
