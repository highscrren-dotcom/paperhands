# Дизайн №120: устойчивость авторов через месяцы (наводка Петра 23.07 19:30-36)

> Статус: ДИЗАЙН-ДОК, анализ session 17. Реализация — ОТДЕЛЬНАЯ сессия.
> Наводка Петра: «кормить в симулятор один символ и один месяц → симулятор даст
> лучших авторов; взять лучших из лучших, которые есть в КАЖДОМ месяце; тупо
> работать по ним окном. Промежуточные точки закодить агентом». Его скрипт
> dump_ideas.mjs (двухфазный скрейпер: symbol-ленты → пул авторов → полные
> ленты топ-авторов, инкрементально, снапшоты лайков) — источник свежих данных;
> исторический архив 2022-2026 у нас уже локально.

## Почему это статистически другой фильтр (а не «ещё раз то же»)

Одномесячный hit-rate (похоронен big-tune №119, p=0.83): монеточник проходит
`track≥2, rate≥0.5` с P≈25-37% → из ~150 авторов/мес десятки ложных.
K-месячная устойчивость: P(luck)≈0.3^K → K=4: ~1 ложный на пул, K=6: ~0.1.
Фильтр давит multiple testing экспоненциально — ровно то, чего не хватало.

## Три ловушки (контроли обязательны, объявляем ДО прогона)

1. **Устойчивость ≠ скилл, может быть = плодовитость.** Оцениваемость в каждом
   месяце требует постить каждый месяц → фильтр тяготеет к конвейерным
   авторам (TradingShot и пр.). Контроль: placebo-выборка авторов с ТЕМ ЖЕ
   профилем активности (число идей/мес), прогнанная через тот же фильтр.
2. **Устойчивость направления ≠ устойчивость прогноза.** Пермабир «стабилен»
   весь медвежий 2022 (наш big-tune: 2022 единственный плюс, +2.8%). Контроль:
   синтетические авторы «always-long»/«always-short» с профилем активности
   выживших — их форвард-результат = планка, которую реальные обязаны бить.
   Плюс требование min доли обоих направлений у кандидата ИЛИ стратификация
   оценки по режимам.
3. **Тюн критериев по результату.** Параметры фильтра (K, порог rate, min
   идей/мес) объявляются заранее, максимум 2-3 варианта, все репортятся.

## Пайплайн (4 фазы, каждая с чекпойнтом — «промежуточные точки» Петра)

**A. Помесячные authorStats** (дёшево: authorStats не зависят от грида —
   Simulator.run с 1-точечной сеткой, только профили): для каждого месяца
   2022-01..2026-07 × BTCUSDT → `authors-YYYY-MM.json` (author, ideas, hits).
   ~1-2ч на всё, резюмируемо помесячно. Расширение на 10 символов скрейпера —
   опционально второй волной (пулит трек автора кросс-символьно).

**B. Матрица устойчивости** (чистая арифметика, без свечей): автор × месяц →
   hitRate/n. Кандидат-критерии (объявлены сейчас):
   - v1: активен ≥K из K трейлинг-месяцев, hitRate≥0.55 в ≥80% активных, ≥3 идеи/мес;
   - v2: то же с hitRate≥0.6;
   - K ∈ {4, 6}. Итого 4 варианта, все в отчёт.

**C. Форвард-оценка** (честный rolling, без look-ahead): вайтлист месяца M
   строится ТОЛЬКО по [M−K..M−1] → Simulator.test на M с фикс-выходами его
   демо (H=5/TT=2/lock=2.5/72ч — НЕ перетюниваем) → ~40+ пар.

**D. Контроли форварда**: (1) placebo-авторы с матч-профилем активности через
   тот же стабфильтр; (2) always-long/always-short с профилем выживших;
   (3) знаковый тест real vs placebo-медиана пары.

**Критерий успеха (заранее):** медианный форвард real-вайтлиста > медианы
placebo-распределения (p<0.05) И > обоих направленческих бейзлайнов.
Иначе — ветка закрыта окончательно, с цифрами по всем 4 вариантам.

## Замечания по данным

- Ранние годы жидкие (медиана 84 BTC-идеи/мес) — устойчивость реально
  оцениваема с ~2024; репортить отдельно 2024+ и полный период.
- Свежесть: архив до 2026-07; скрейпер Петра (dump_ideas.mjs) можно поставить
  кроном на сервер для форварда — отдельное ops-решение, не для этой ветки.
- Всё на локальных свечах датасета, движок 16.5.0+, сиды детерминированы.
