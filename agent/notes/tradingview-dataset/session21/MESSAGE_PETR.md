## 2. Консенсус толпы — закрыт

Сначала воспроизвёл твои числа: LONG все −952.8 % / 2576, консенсус −744.9 % / 2091
совпали точно, SHORT счётчики 1356 и 536 тоже.

В `consensus_all.py` и `entry_filter.py` окно согласия симметричное:

```python
same = sum(1 for o in ts if abs(o['entryTimestamp']-t['entryTimestamp'])<=W and o['direction']==D)
```

`abs(...) <= W` — это `[t−W, t+W]`, в согласие попадают идеи, опубликованные после
входа. На момент сделки их нет.

Причинное окно `[t−W, t]`:

| | ±24 ч (твоё) | [−24 ч, 0] | без фильтра |
|---|---|---|---|
| SHORT, на сделку | −0.296 % | **−0.459 %** | −0.461 % |
| LONG, на сделку | −0.356 % | −0.394 % | −0.370 % |

Причинный консенсус на SHORT равен отсутствию фильтра. Улучшение с −0.461 до
−0.296 целиком создают будущие идеи.

Дальше по твоему ТЗ:

- **полная сетка** (108 комбинаций, W 6–72 ч × same>opp / перевес≥K / доля≥R ×
  два направления): 5 положительных ячеек, все на 1.5–13 % выборки, плюсовых
  месяцев 3–14 из 67, соседи отрицательные — твой же методический пункт 7;
- **walk-forward** (12 мес обучения → следующий): SHORT выбранный фильтр
  −0.488 %, без фильтра −0.402 %, случайный фильтр −0.090 %. Подобранное хуже
  случайного, параметр скачет каждый месяц;
- **детектор режима**: лучший признак — PnL прошлого месяца, r = +0.223.
  Перекос ленты работает наоборот: у мёртвых месяцев +0.279, у живых +0.400.

Ни один критерий приёмки из раздела 10 не выполнен. По твоей же формулировке —
это полноценный результат, направление закрыто.

## 3. Вопрос: гоняем другие тикеры?

**Наше мнение — да, гонять и расширять список авторов.** Причина конкретная.

Посмотрел ленту идей по символам и сверил с составом датасета. Пять тикеров с
хорошим покрытием толпы в датасет не попали вообще:

| символ | направленных идей | месяцев | в датасете |
|---|---|---|---|
| XRPUSDT | 1052 | 60 | нет |
| BNBUSDT | 947 | 63 | нет |
| ADAUSDT | 905 | 62 | нет |
| LINKUSDT | 894 | 63 | нет |
| AVAXUSDT | 729 | 67 | нет |
| LTCUSDT | 310 | 63 | нет |
| — | | | |
| TRXUSDT | 124 | 42 | да |
| ZECUSDT | 116 | 30 | да |
| NEARUSDT | 82 | 37 | да |

То есть внутри уже посчитаны тикеры с 82–124 направленными идеями за всю
историю, а XRP с 1052 и BNB с 947 отсутствуют. Пять недостающих дают +4527
направленных идей — это +43 % к текущим 10 527 по всему датасету.

Что это даёт по существу, а не «для объёма»:

1. **Независимая проверка находки.** У тебя все PnL-расчёты только по BTCUSDT
   (24 часа на все символы). Мой лифт +0.70 % посчитан по 12 символам сразу, но
   половина объёма — это BTC. Пять новых крупных тикеров — это честный
   out-of-sample для отбора авторов на данных, которых он не видел.
2. **Пул кандидатов.** Сейчас порог ≥10 идей за 12 месяцев проходит 61 автор.
   Топ-3 дают ~16 сделок в месяц — для живого портфеля это мало. Больше рынков —
   больше авторов проходит порог и больше одновременных сигналов.
3. **Проверка на переносимость.** Если автор хорош на BTC и ETH, но разваливается
   на XRP и BNB — это про режим, а не про навык, и это надо знать до денег.

**Порядок важнее объёма.** Если запускать перегенерацию, то делать это одним
заходом и сразу с расширенными осями:

- продлить `profitLockPercent` за 5 % (например до 8) и `trailingTakePercent` за
  5 % (до 8). Это решающая проверка находки: она сидит ровно на краю сетки, и
  сейчас непонятно, склон это или обрыв;
- добавить XRP, BNB, ADA, LINK, AVAX (LTC по желанию).

Расширение осей увеличит сетку примерно вдвое, пять тикеров — примерно в
полтора раза по объёму. Место под это есть: 100 ГБ тома с zstd, сейчас занято
26 ГБ физически при 64 ГБ логических, то есть запас втрое.

Если делать что-то одно — сначала оси. Если находка на краю не подтвердится,
новые тикеры считать смысла нет.
