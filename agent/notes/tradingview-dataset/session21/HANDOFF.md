## Решение по правке движка

Петр разрешил редактировать `backtest-kit` в `node_modules`. **Не делаем — не нужно.**

- Сетка: `gridAxes` это параметр `addSimulatorSchema`, дефолт 21 280 переопределяется
  из раннера (его собственный пример walk-forward в README это и делает).
- Издержки: пакет экспортирует `setConfig({ CC_PERCENT_FEE, CC_PERCENT_SLIPPAGE })`
  (`types.d.ts:8632`) — тоже userspace.

Оба нужных эксперимента идут на стоковом пакете, значит Петр воспроизводит наши
числа у себя без плясок. Правка `node_modules` не версионируется и стирается любым
`npm i`. Разрешение приберечь для того, где оно реально понадобится: Sweep /
консенсус / портфель с общим капиталом внутри движка (сейчас доктрина
`ClientSimulator` это прямо запрещает: авторы грейдятся изолированно, роевой
рейтинг — userspace).

## Фаза A — решающий эксперимент (следующий шаг)

**Вопрос:** находка сидит ровно на краю сетки (лок 5 % и трейл 5 % — максимумы осей),
при локе 4 % знак лифта переворачивается. Склон настоящего холма или стенка сетки?

**Как:** узкая окрестность за краем, 450 точек вместо 21 280.

```js
// @ts-check
/** @typedef {import("backtest-kit").ISimulatorGridAxes} GridAxes */
/** @type {GridAxes} */
const gridAxes = {
  hardStopPercent:     [8, 8.5, 9, 9.5, 10],          // 5
  trailingTakePercent: [3, 4, 5, 6, 7, 8],            // 6  — за 5 % впервые
  holdMinutes:         [12*1440, 13*1440, 14*1440],   // 3
  profitLockPercent:   [4, 5, 6, 7, 8],               // 5  — за 5 % впервые
};
```

**Почему дёшево:** глубина профиля идеи = `max(holdMinutes)` (`HORIZON_MINUTES_FN`).
Ось hold не трогаем, максимум остаётся 20160 мин → движок просит ровно те свечи,
что уже лежат в `dump/` (79 ГБ логических во всех 67 пакетах, промахов быть не
должно, сеть не нужна). Сетка меньше в 47 раз.

**Вывод не через `result_reports.jsonl`** (там `tradesList`, на расширенной сетке
это терабайты), а компактной панелью прямо из колбэка:

```js
callbacks: {
  onGridPoint(symbol, report, trades) {
    const p = report.point;
    const per = new Map();
    for (const t of trades) {
      const q = per.get(t.author) ?? [0, 0];
      q[0] += 1; q[1] += t.pnlPercent;
      per.set(t.author, q);
    }
    const rule = `${p.holdMinutes}\t${p.profitLockPercent}\t${p.hardStopPercent}\t${p.trailingTakePercent}`;
    let out = "";
    for (const [a, [n, pnl]] of per) out += `${MONTH}\t${symbol}\t${rule}\t${a}\t${n}\t${pnl.toFixed(4)}\n`;
    appendFileSync(OUT, out);
  },
}
```

Формат совпадает с тем, что едят готовые скрипты анализа (`month symbol hold lock
stop trail author trades pnl`). Объём ~1 МБ на тикеро-месяц, ~0.5 ГБ на всё.

**Практика запуска.** Кэш свечей движка читается относительно `cwd` (`./dump`),
поэтому либо запускать с `cwd` внутри его месячного пакета, либо свой каталог с
симлинком на `dump` нужного месяца. Hardlink-копию кэшей НЕ делать: 79 ГБ — это
десятки миллионов мелких файлов (в jun_2026 одном 517 783), скопируются часами и
сожрут inode-ы. Долгие прогоны только через `nohup`/`setsid` + лог, шардить по
месяцам на 4–5 процессов, `nice -n 10 ionice -c3` (на CT102 живёт боевой стек).

**Критерий приёмки Фазы A:** лифт отбора авторов считается на новых точках тем же
walk-forward (скрипт `analyze5.py`, функция `run`). Смотреть монотонность по локу
4 → 5 → 6 → 7 → 8 и по трейлингу 3 → 8:

- лифт продолжается или выходит на плато за 5 % → находка настоящая, идём в Фазу B;
- лифт пикует ровно на 5 % и падает за краем → это была стенка сетки, направление
  «отбор авторов» закрывается так же, как консенсус.

## Фаза A2 — издержки (можно параллельно, дёшево)

Единственный непроверенный рычаг Петра, который бьёт в причину убыточности, а не в
симптом: сигнал в ленте есть (медианное окно без издержек +101.5 %, с издержками
−52.5 %), он просто меньше 0.4 % на круг.

```js
import { setConfig } from "backtest-kit";
setConfig({ CC_PERCENT_FEE: 0.02, CC_PERCENT_SLIPPAGE: 0.05 });  // мейкерские лимитки
```

Прогнать ту же сетку (или её часть) с мейкерскими издержками и посмотреть, какая
доля из 21 280 точек переходит в плюс. Это НЕ доказательство прибыльности —
мейкерский вход не гарантирован, лимитка может не исполниться, — но показывает,
сколько стоит исполнение и есть ли вообще запас.
