# Петру: проверил ботов перед постом. Координации нет, но твой вопрос «кто пишет рано» дал зацепку

## Коротко

Догадку «сначала боты, потом автор» прогнал целиком: кластеры постов, фильтр по шуму,
совстречаемость аккаунтов, косинусная близость заголовков (твой метод из статьи).
Торгуемой координации нет. А вот «кто пишет в первую половину, пока толпа не поперла» —
единственный отбор авторов, который пережил контроли за все четыре фазы. С оговорками,
ниже честно.

## 1. Кластер ничего не предсказывает вперёд

Кластер = N постов по символу за окно. Сетка N 3/5/8, окно 6/24 ч, 10 167 идей,
холд 14 сут, твои издержки 0.4 % на круг. От каждого кластера четыре входа:

| вход | лучшая ячейка (3 поста / 6 ч) |
|---|---|
| в начале кластера | +0.334 |
| по посту (как сейчас) | +0.290 |
| когда кластер стал виден | +0.288 |
| buy & hold от начала | −1.075 |

Разница «начало против поста» — четыре сотых процента на сделку. И главное: сдвигаю
все кластеры на случайные ±1..30 суток — зарабатывают столько же (p 0.48–0.75 по всем
ячейкам). А кластеры, собранные из постов по ДРУГИМ монетам, на этой монете платят
даже больше настоящих. То есть «кластерность» ловит общий дрейф рынка, а не вброс в
конкретную монету. Пост стоит в конце движения — это же показал сдвиг назад в фазе C,
теперь закрыто с обеих сторон.

Фильтр «не входить, когда уже шумно» тоже проверил на твоём правиле (лок 20 / трейл 8 /
топ-2): базлайн 264 сделки, лифт над лонгом +1.493 (t 2.28); с порогом «меньше 3 чужих
за сутки» — 201 сделка, лифт +1.137; «меньше 4» — 231 и +1.031. Фильтр режет прибыльные
входы наравне с убыточными. В рецепт не вносить.

## 2. Ботов в данных не видно

- `isScript` = 0 у всех 52 тысяч постов — поле пустое, прокси не работает.
- Pro-аккаунтов среди ранних постов МЕНЬШЕ (63 % против 69 % у поздних) — «сначала
  боты, потом Pro-автор» наоборот не сходится.
- Заголовки внутри кластеров сравнил твоим методом (косинус, KNN), вектора — символьные
  3-граммы: шаблонных кластеров 4.6 % при 3.2 % ожидаемых по шуму. Массовой сети нет.
  Единичные клоны есть: Apex_Legends и XAUxBTC_Pro постят одинаковые заголовки
  (5 случаев), Greattradinglab / aliarefiasl4147 / iamhitendra — идентичные тайтлы в
  июле 2026. Десяток пар на 13.7 тыс. постов — карлики.
- Совстречаемость: 24 пары «Y систематически стоит перед X» на p ≤ 0.01 против ~6
  случайных. BitCoinGuide стоит перед шестью разными авторами чаще, чем даёт сдвиговый
  нуль. Но ровно такой же избыток даёт обычная реакция двух аккаунтов на одно и то же
  движение, а пункт 1 показал, что тайминга вперёд в этом нет. Так что читать как
  координацию оснований нет.

## 3. Что дал твой вопрос «кто именно пишет в первую половину»

Ранность (доля постов автора при ≤2 чужих за сутки до) — устойчивое свойство: r = 0.77
между первой и второй половиной ленты автора. И отбор по ней работает без подглядывания
в PnL: топ-2 по ранности прошлых 12 мес, walk-forward:

| отбор | на сделку | против жребия |
|---|---|---|
| топ-2 по ранности | +3.060 (304 сд.) | p = 0.005, 1000 жеребьёвок |
| только их ранние идеи | +4.286 | p = 0.001 |
| топ-2 по PnL (фаза C) | +0.675 | неотличим от жребия |

Кто это: стабильно ранние с плюсом — DHLawrence (84 % ранних, +4.5 на ранних),
coinpediamarkets (76 %, +3.9), drcrypto14 (85 %, +2.9), BallaJi (78 %, +1.7),
jhonnybrah (80 %, +0.8). Антипример: Solldy ранний, но −1.2 — ранность сама по себе
качества не гарантирует, работает именно связка «рейтинг за прошлый год → следующий
месяц».

Теперь честно, почему я это в рецепт НЕ вношу:

- значимость сидит в заявленном определении «≤2 чужих / 24 ч»; соседние (≤1, ≤3, окно
  6 ч) дают тот же знак, но p 0.03–0.60;
- по годам: 2023 +5.5, 2024 +8.0, а 2025 −1.4 — год из пяти в минусе;
- над «теми же входами, но просто в лонг» прибавка +0.88 при t 0.83 — деньги в большой
  мере делает попадание в лонг-волну, а не сторона.

По меркам, которыми мы убили отбор по PnL, это «похоже на правду», а не «доказано».

## Что делать

Различить «ранние видят раньше» и «повезло с определением» может только живой скрейп:
в бэкфиле firstSeen один на весь датасет, порядок появления постов восстановить нельзя.
Если скрейпер начнёт писать per-idea firstSeen сейчас, через 2–3 месяца будет честный
out-of-sample на данных, которых при подгонке не существовало. Это дешевле любого
нового бэктеста и закрывает вопрос навсегда.

Ранность на твоей стороне считается без движка, чистый препроцесс перед Sweep:

```js
// ранность авторов и отбор топ-2 перед Sweep.run (17.6.0)
function pickEarlyAuthors(ideas, testMonth, K = 2, EARLY_MAX = 2, WIN_H = 24) {
  const from = monthAdd(testMonth, -12), to = testMonth;      // прошлые 12 мес
  const bySym = groupBy(ideas, (i) => i.symbol);              // ВСЕ посты, и NEUTRAL
  const stat = {};                                            // author -> [ранних, всего]
  for (const list of Object.values(bySym)) {
    list.sort((a, b) => a.ts - b.ts);
    let lo = 0;
    list.forEach((idea, hi) => {
      if (idea.ts < from || idea.ts >= to || idea.direction === "NEUTRAL") return;
      while (list[lo].ts < idea.ts - WIN_H * 3600e3) lo++;
      let others = 0;
      for (let j = lo; j < hi; j++) if (list[j].author !== idea.author) others++;
      const s = (stat[idea.author] ??= [0, 0]);
      s[0] += others <= EARLY_MAX ? 1 : 0;
      s[1] += 1;
    });
  }
  return Object.entries(stat)
    .filter(([, s]) => s[1] >= 10)                            // допуск 10 идей
    .sort((a, b) => b[1][0] / b[1][1] - a[1][0] / a[1][1])
    .slice(0, K)
    .map(([author]) => author);
}

const early = pickEarlyAuthors(allIdeas, monthStartTs);
const result = await Sweep.run({
  symbol,
  sweepName: "tv_hold",
  ideas: ideas.filter((i) => early.includes(i.author)),
});
```

Сетку и схему `addSweepSchema` менять не надо — отбор целиком снаружи.

посту, чёрный список вместо белого. Ни кластеры, ни фильтр шума его не улучшают.
