# FORWARD-ПРОТОКОЛ pump-пути (этап A дорожной карты live)

> Действует с 2026-07-08. Решение владельца: «live по ускоренной программе,
> идём по пятам автора, рискуем только малыми суммами» + явное «Да, погнали».
> Механика: `example/scripts/pump_bench/{fit_forward,forward}.mjs`.

## Суть

Живой Telegram-ingest (backtest-ollama-crontab, крутится с 2026-07-07) кормит
**замороженную** модель pump-anomaly 2.0.0; каждое решение и каждый реализованный
исход пишутся в append-only леджер. Это форвард-OOS: данные, которых не видел
ни наш fit, ни автор при дизайне библиотеки.

## Замороженная модель

- `assets/forward-model-v1.json` — fit на ВСЕЙ истории канала (414 постов,
  apr-2025..apr-2026), библиотека pump-anomaly **2.0.0**; паспорт —
  `out/forward-model-v1-info.json` (deployment/сертификат/exit-конфиг).
- **Рефитов внутри окна НЕТ.** Рефит = новая версия (v2) = новое окно с нуля.
  (Адаптивный рефит — тезис автора из edge-reality тестов — проверим ПОСЛЕ
  того, как статичная v1 отработает окно: сравнение v1 vs еженедельные рефиты
  станет отдельным экспериментом.)

## acknowledgeUncertified — задокументированное решение

pump-anomaly 2.0.0 сама блокирует live-сигналы несертифицированной модели
(`deployment.verdict="paper"`). Мы передаём `acknowledgeUncertified: true` —
по терминологии автора это «осознанный форвард на бумаге/микро». Решение
принято владельцем 2026-07-08 в рамках ускоренной программы. Деньги на этом
этапе НЕ рискуются: форвард бумажный.

## Механика (forward.mjs, cron ежечасно)

1. **DECIDE**: новые `parser-items` из Mongo → ParserItem → `plan()` (свечи
   строго до сигнала — live-семантика) → `out/forward-ledger.jsonl`:
   item + сигнал/отсечка + `explainSignals` (кто отсёк и почему — capacity,
   momentum-gate и т.д.). Идемпотентно по `_id`.
2. **EVALUATE**: записи с сигналом старше `staleMinutes·2+5` (~24ч) реплеятся
   `planForAt()` по фактическим 1m-свечам → `out/forward-results.jsonl` +
   сводка (aggregate с epsilon-guard, сырой pnl и haircut 0.4%).

## Гейты выхода из окна (этап D дорожной карты)

Минимум **30–50 реализованных форвард-сигналов**, И:
- mean/сделка после haircut 0.4% ≥ +0.3% И per-trade Sharpe > 0;
- нет катастрофического расхождения с история-OOS (mean форварда ≥ 0.5×
  история-OOS mean — иначе стоп и разбор, кейс clarkkent5);
- сертификация объединённых данных (история+форвард) — отчёт владельцу,
  даже если снова красная (тогда микро-live только отдельным решением).

При прохождении → этап E: брокер-адаптер + микро-сайз (сумма — отдельное
решение владельца).

## Честные оговорки

- pnl леджера СЫРОЙ: комиссия/слиппедж/фандинг/спред не моделируются;
  haircut 0.4%/раунд-трип в каждой сводке.
- Шорты ~половина сигналов — исполнимость (фьючи vs long-only спот) решается
  до этапа E (открытый вопрос владельцу №8).
- Один канал → mode=single: матричные фичи (author-dedup, cascade по
  кластерам) в форварде не проверяются.
- Дрейф шаблона канала ~ежемесячный: ловим по `Parsed/extracted:null` в логе
  ingest (алерт — TODO в backlog) и по падению частоты новых parser-items.

## Операционка

- Ingest: `backtest-ollama-crontab`, paper-процесс (pid в `logs/paper-ingest.pid`),
  Mongo `backtest-pro`, скрейп каждые 15 мин, UI :60050.
- Форвард: cron ежечасно (лог `out/forward-cron.log`). Установка (одной командой
  владельца; агенту запись в crontab запрещена политикой):

  ```bash
  (crontab -l 2>/dev/null; echo '25 * * * * cd /home/s1dd1/dev/quant/paperhands/example && /home/s1dd1/.nvm/versions/node/v24.17.0/bin/node scripts/pump_bench/forward.mjs >> scripts/pump_bench/out/forward-cron.log 2>&1') | crontab -
  ```
- Уязвимость: ребут машины кладёт и ingest, и Mongo (docker restart=always
  поднимет Mongo; paper-процесс НЕ переживёт — durable-вариант = этап B,
  redis-mongo-персистенция + docker).
