# Промпт строителю: tg-claude-bridge — визуальное меню (фаза 3)

Продолжение сервиса `/home/s1dd1/dev/quant/tg-claude-bridge/` (фазы 1 и 2
приняты главной сессией 18.07; репо highscrren-dotcom/backtest-claude-telegram

«чистый визуальный с меню, чтоб дублировались команды введя слеш, должен
предлагать нажать старт и после выводить меню».

## Что сделать (три вещи)

### 1. Слеш-меню Telegram (setMyCommands) — «дублировались команды введя слеш»
На старте моста (в main(), рядом с getMe) вызвать `setMyCommands` со списком
команд и описаниями — тогда при вводе `/` Telegram сам показывает автодополнение.
Список (scope по умолчанию; язык ru):
- `start` — Запустить / показать меню
- `sessions` — Список сессий (кнопки)
- `new` — Новая сессия
- `ping` — Статус моста
- `sid` — ID текущей сессии
- `name` — Переименовать текущую сессию
- `use` — Переключиться на сессию N
Идемпотентно (setMyCommands перезаписывает). Сбой вызова — не фатальный,
только slog (мост работает и без меню-регистрации).

### 2. Кнопка «Start» и приветствие — «предлагать нажать старт»
Для нового чата Telegram сам рисует кнопку Start (шлёт `/start`). Дополнительно
поставить menu-button через `setChatMenuButton` (type: "commands") — слева от
поля ввода появится кнопка «Меню» со списком команд. На `/start` мост отвечает
приветствием + постоянным меню (см. п.3).

### 3. Постоянное визуальное меню (ReplyKeyboard) — «после выводить меню»
На `/start` (и командой `/menu`) слать reply_markup с `keyboard` (НЕ inline —
это нижняя постоянная клавиатура, кнопки шлют текст как обычные сообщения,
новых типов апдейтов НЕ требуют — остаёмся в message+callback_query):
```
[ 📋 Сессии ]  [ 🟢 Статус ]
[ 🆕 Новая  ]  [ 🏷 Имя    ]
```
- «📋 Сессии» → шлёт `/sessions`; «🟢 Статус» → `/ping`; «🆕 Новая» → `/new`;
  «🏷 Имя» → подсказка «пришли: /name <текст>» (у /name нужен аргумент).
- `resize_keyboard: true`, `is_persistent: true`, `input_field_placeholder`
  типа «команда или текст для Claude». Кнопки-эмодзи-подписи мост должен
  распознавать в handleUpdate ДО отправки в claude: если текст входящего ==
  одной из кнопок-подписей → маппить на соответствующую команду (иначе «📋
  Сессии» уйдёт как промпт в claude). Держать маппинг подписей в одном месте.
- `/menu` — показать клавиатуру повторно (на случай если свернул).

## Инварианты (НЕ ослаблять — иначе приёмка не пройдёт)

1. Никаких новых типов апдейтов: reply-keyboard кнопки шлют обычные message.
   allowed_updates остаётся [message, callback_query] (callback уже для сессий).
2. setWebhook НЕ вызывать. Токен из боевого .env, не хранить. deny-профиль
   settings.claude.json НЕ трогать.
3. Маппинг кнопка→команда — только для ALLOWED_CHAT_ID (уже гейт classifyUpdate).
4. Кнопки-подписи не должны случайно глотать легитимный текст: маппить лишь
   ТОЧНОЕ равенство подписи, не подстроку.
5. Тексты через reply() (редакция на месте). Меню — plain, без parse_mode.

## Чеклист приёмки (выполнит главная сессия)

1. Ввод `/` в телеге → выпадают 7 команд с описаниями (setMyCommands);
2. кнопка «Меню» у поля ввода открывает список команд (setChatMenuButton);
3. `/start` → приветствие + нижняя клавиатура из 4 кнопок;
4. тап «📋 Сессии» → приходит список сессий (как /sessions), НЕ уходит в claude
   как промпт; то же для «🟢 Статус»→/ping, «🆕 Новая»→/new;
5. «🏷 Имя» → подсказка про /name <текст>, не пустой /name;
6. `/menu` возвращает клавиатуру; обычный текст (не подпись) по-прежнему уходит
   в claude штатно;
7. фазы 1–2 целы: deny (systemctl→отказ), /sessions-кнопки-tap, secret-redact,
   чужой from.id → drop; тесты node --test зелёные;
8. скан секретов диффа перед готовностью (в репо токена нет).
