# Ломающие изменения — ветка `simulator` против `master`

> Файл Петра, передан владельцем 24.07.2026 как ответ на план роевого стенда.
> Исходник пришёл с битой кодировкой (двойной UTF-8); ниже — восстановленный
> текст, сверенный по структуре. Оригинал у владельца.

Область: сущность Simulator (`Simulator.run` / `Simulator.test`), её схемные
контракты и CLI-команды `--simulator` / `--tune`. Обратная совместимость
намеренно НЕ сохраняется — корректность важнее BC.

## 1. Метрики взаимодействия авторов ВЫРЕЗАНЫ — авторы оцениваются изолированно

Удалено из `ISimulatorGridAxes`, `ISimulatorGridPoint` и всех правил:

- `minIdeasAligned` — подсчёт консенсуса в скользящем окне;
- `minWeightAligned` — консенсус, взвешенный трек-рекордом;
- `minAuthorWilson` — порог бана по нижней границе Вильсона (95%).

Движок теперь оценивает каждого автора СТРОГО изолированно: число hit'ов
автора зависит только от свечных траекторий его собственных идей. Никаких
консенсусов, весов голосов и взаимодействий в движке не существует. Роевое
ранжирование (рейтинг авторов на длинных историях, межавторская агрегация) —
юзерспейс: считайте его на своём датасете и возвращайте результат через
замороженные статы `Simulator.test`.

## 2. `banCriteria` ВЫРЕЗАН — никакой межметричной агрегации

`ISimulatorGridAxes.banCriteria` (какие победители рейтингов кормят ран-левел
белый список) удалён вместе с самой ран-левел агрегацией, которую он
настраивал. Ничто больше не склеивается между метриками и критериями (см. §3).

## 3. `ISimulatorResult` перестроен — корзины по метрикам

Форма master:

- `reports: ISimulatorPointReport[]` — один плоский список, отсортированный
  по `reportOrder`;
- `best: ISimulatorBest[]` — четыре глобальных победителя рейтингов;
- `allowedAuthors` / `bannedAuthors` — ран-левел списки
  (объединение/пересечение).

Новая форма:

- `reports: Record<SimulatorAuthorMetric, ISimulatorMetricReport>` — по
  корзине на метрику авторского hit'а, у каждой СВОИ `reports`
  (отсортированы по `reportOrder`), СВОИ победители `best` и СВОИ `bans`;
- глобальных `best`, `allowedAuthors` и `bannedAuthors` БОЛЬШЕ НЕТ —
  несравнимые грейдинги никогда не агрегируются;
- `bans: ISimulatorRuleBans[]` (новый контракт) — по записи на уникальное
  правило бана, чистая арифметика порогов (никакого ранжирования),
  самоидентификация собственными полями: `holdMinutes`, `minAuthorTrack`,
  `minAuthorHitRate` плюс уровни правила (`profitLockPercent` у
  reach/retain, `hardStopPercent` у reach, `trailingTakePercent` у trail).
  Несёт `authorStats`, `allowedAuthors`, `bannedAuthors` строго правила;
- `onRanking` теперь стреляет по разу на (вымеряемая метрика x критерий),
  а не по разу на критерий;
- миграция: `result.reports.close.best.find(({ criterion }) => ...)`
  вместо `result.best.find(...)`;
  `Object.values(result.reports).flatMap((b) => b.reports)` вместо
  `result.reports`.

`ISimulatorTestResult` сохраняет свои `allowedAuthors` / `bannedAuthors` —
тест оценивает ровно одно замороженное правило, списки однозначны.

## 4. Метрики авторов: два новых грейдинга, всего пять

`SimulatorAuthorMetric` был `"close" | "reach"`; теперь
`"close" | "reach" | "retain" | "pnl" | "trail"`:

- `"retain"` — ФИКСАЦИЯ уровня: медиана хода окна строго выше
  `profitLockPercent` точки;
- `"pnl"` — MFE окна вырос БОЛЬШЕ фиксированного порога +1%, независимо
  от уровней точки;
- `"trail"` — лучшая экскурсия дотянулась до уровня ВЗВОДА трейлинга
  точки (`entry/(1 - r)`) — симметрия reach для trailing-точек.

`SimulatorAuthorRule` — дискриминированный union; КАЖДЫЙ вариант теперь
несёт `holdMinutes` (см. §5) и только свои уровни: reach — замок + стоп,
retain — замок, trail — трейлинг, close/pnl — только пороги.

Дефолтная ось `authorMetric`: `["close", "reach"]` →
`["close", "reach", "retain", "pnl", "trail"]`.

## 5. Окно грейдинга = холд собственной точки (было: жёсткий 5-дневный горизонт)

- Зашитого 5-дневного горизонта идеи (`IDEA_TRIM_DAYS`) НЕ СУЩЕСТВУЕТ.
  Глубина скачки свечей профиля — самый длинный холд сетки,
  `max(holdMinutes)` схемы. Горизонтом владеет схема.
- Каждая метрика автора считается ВНУТРИ ОКНА ХОЛДА СВОЕЙ ТОЧКИ — первые
  `holdMinutes` свечей траектории идеи. Две точки с разными холдами в одной
  сетке судят одного автора по-разному и тренируются раздельно (окно —
  часть идентичности правила бана и ключа мемоизации).
- Идея — улика для правила только когда окно ПОЛНОСТЬЮ наблюдено;
  обрезка краем данных короче окна ничего не доказывает для этого правила
  (правило с более коротким окном ту же идею ещё может засчитать).
- Агрегатные поля профиля (`hit`, `maxMfePercent`, `medianMovePercent`,
  `shakeoutMaePercent`, ...) — только полногоризонтная ДИАГНОСТИКА;
  тренировка банов их не читает.
- Клампа холда к горизонту профиля больше нет: холд сам задаёт горизонт,
  20-дневный холд строит 20-дневный профиль.

## 6. Вырожденных точек сетки НЕ СУЩЕСТВУЕТ — никаких тихих фолбэков

Master молча перегрейдировал `reach`-точку с `profitLockPercent = 0` как
`"close"`. Теперь:

- точки `reach` и `retain` с `lock = 0` исключаются из декартова
  произведения;
- точки `trail` с `trailingTakePercent` вне `(0, 100)` исключаются;
- сетка, ПУСТЕЮЩАЯ из-за исключений, громко падает в `run()` вместо
  тихой тренировки под правилом другой метрики.

## 7. CLI

- `--simulator`: хардкод сетки пробы удалён. Сетка приходит ОПЦИОНАЛЬНЫМ
  позиционным JSON-конфигом `{ "gridAxes"?, "reportOrder"? }`; без него
  используется пустой объект и действуют дефолты движка. Неизвестный ключ
  конфига обрывает запуск.
- `--tune`: БОЛЬШЕ НЕ ОБУЧАЕТ. `Simulator.run`, walk-forward-сплит и флаг
  `--split` удалены. Команда — ОДИН out-of-sample выстрел замороженного
  артефакта обучения, передаваемого ОБЯЗАТЕЛЬНЫМ позиционным JSON-конфигом
  `{ "point", "authorStats", "gridAxes"?, "reportOrder"? }`, через
  `Simulator.test`; `--json` сохраняет `ISimulatorTestResult`.
