# PLAN — развитие paperhands (форк backtest-kit)

> Контекст: репозиторий — форк `tripolskypetr/backtest-kit` (см. [../CLAUDE.md](../CLAUDE.md)),
> работаем в [`../example`](../example/). Разбор первоисточника — [ANALYSIS.md](ANALYSIS.md).
> Порядок жёстко по инварианту **backtest → paper → live**; цель — прибыль, но
> честная (через OOS-гейт), а не красивая одномесячная цифра.

## Что фреймворк уже даёт (не переизобретаем)

look-ahead вшит в ядро (`ClientExchange.getCandles`, `AsyncLocalStorage`-часы);
слиппедж 0.1% + комиссия 0.1% в PnL; **paper и live реализованы**; богатая модель
позиции (scheduled/limit, timeout `time_expired`, breakeven, partial, trailing, DCA
с гвардом cost-basis); транзакционный брокер + crash-recovery; риск-слой с
портфельным резервом; честные метрики (Pooled Sharpe, `N/A` вместо фейка, гейты
≥10 сигналов / ≥14 дней); Pine (PineTS); ccxt-данные с кэшем.

**Наш вклад поверх (проектный слой, ядро не трогаем):** OOS/walk-forward-гейт
против переобучения (его в фреймворке нет — его доктрина «один месяц» + paper) и
дисциплина evidence-first в отчётах.

## Принципы

- Маленькие шаги; git diff перед коммитом; без OK не коммитить.
- **Ядро (`src/**`) не редактируем** — форк держим ребейзабельным на upstream; наши
  вещи в `agent/` и в проектных скриптах `example/`.
- Look-ahead абсолютен; funding/спред фреймворк не моделирует — помним про них.
- Прибыльность не обещаем; нет эджа — фиксируем честно (это и доктрина backtest-kit).

## Phase 0 — Верификация дословного старта  ⏳ в процессе

`npm install` в `example/` ✓ (458 пакетов, exit 0). Прогон
`npm start -- --backtest --symbol TRXUSDT ./content/jan_2026.strategy/jan_2026.strategy.ts`.
**Приёмка:** получен реальный вывод; сверяем механику (комиссия 0.1%+слиппедж 0.1%,
close-reason'ы `take_profit/stop_loss/time_expired`, метрики Sharpe/PnL) с докой и
моими описаниями. Если падает — разбираем (напр. postinstall `ccxt`).

## Phase 1 — Освоить рабочий цикл на example

Изучить 1–2 стратегии графом codebase-memory + чтением: `jan_2026` (инверт-Telegram,
Sharpe 1.14) и `dec_2025` (Pine range breakout). Понять контракт `getSignal`,
реактивный слой `listen*`/`commit*`, `dump/` и JSONL-логи, где считаются метрики.
**Приёмка:** можем объяснить и воспроизвести прогон, читаем лог осмысленно.

## Phase 2 — OOS / walk-forward гейт (наш слой)

Проектный скрипт поверх штатного `--backtest`: гоняем одну стратегию по **нескольким
месяцам/окнам**, агрегируем Sharpe / деградацию / max drawdown / vs buy&hold, выводим
вердикт «overfit / holds up». Ядро не трогаем. **Приёмка:** гейт ловит одномесячную
удачу — напр. высокий % при низком Sharpe (как Apr 2026 +67.85% / Sharpe 0.12)
помечается как подозрительный, а не «успех».

## Phase 3 — Разработка месячной стратегии по доктрине

**Первая цель (решение владельца): июнь 2026, ETHUSDT.** Июнь закрыт полным месяцем —
свежая выборка, историч. данные доступны.

По [cli/template/project/CLAUDE.md](../cli/template/project/CLAUDE.md): news+`--dump`
анализ рынка месяца → концепт (не brute-force) → `.pine` (`math/`) + обёртка
`content/<month>.strategy.ts` → backtest → `report/<month>.md` → **code-review
отдельным агентом** → прогон через наш OOS-гейт (Phase 2). **Приёмка:** честная шапка
(`sharpeRatio`/`avgPnl`/`stdDev`), ≥1 сигнал/день, TP ≥ 1%, R/R ≥ 2; проходит гейт
или честно фиксируем провал.

## Phase 4 — Paper (ОСНОВНОЙ ПРОГОН)

`--paper`: живые цены, реальных ордеров нет, тот же `getSignal`. Копим форвард-
статистику, сверяем с backtest (расхождение = сигнал переобучения, ровно кейс
clarkkent5). **Приёмка:** paper идёт стабильно; метрики честные; расхождение с
backtest объяснено. Это ступень, которую нельзя пропускать перед деньгами.

## Phase 5 — Live с реальными средствами

Только после устойчивого paper и **отдельного аппрува владельца**. Брокер-адаптер
(ccxt, ключи в `.env`), сухие прогоны хуков `--brokerdebug --commit signal-open`,
**мелкий сайз**, crash-recovery/graceful shutdown. Код стратегии и look-ahead —
идентичны backtest/paper. **Приёмка:** контролируемый мелкий live; метрики честные;
готовность остановиться по просадке.
