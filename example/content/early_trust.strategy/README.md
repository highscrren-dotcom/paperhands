# early_trust — paper-проверка отбора авторов по ранности (фаза D)

Форвард-тест правила, прошедшего контроли на бэкфиле (DECISIONS №137/138/140/142):
**топ-2 автора по доле ранних постов за скользящие 12 месяцев; вход по их идее в её
сторону; холд 14 суток, profit lock 20 %, trailing 8 %, жёсткого стопа нет.**
Бэкфил-ожидание ячейки (K=2, 12 мес): +3.06 %/сделку против поля +0.31 (p = 0.005);
оговорка: 2025 год в минусе — paper это и проверяет.
Статус: PLAUSIBLE — эта стратегия и есть решающая проверка на данных, которых
не существовало при подгонке.

⚠️ **Окно 60 мес для live запрещено**, хотя статистически оно сильнее (p = 0.001):
чистая ранность длинного окна выводит в топ авторов, ушедших с платформы в 2023
(Avramis/Solldy/drcrypto14 молчат 2+ года) — стенд молчал бы вечно. Допуск
≥ 10 идей за 12 мес сам гарантирует живых. Активити-фильтр поверх 60-мес окна —
отдельная НЕвалидированная гипотеза, в прод не тащить без контролей.

## Запуск

```bash
cd example

# смоук на истории (доверенные в июне не постили, поэтому список подменён —
# проверяется механика входа/выхода, не эдж):
cp content/jun_2026.strategy/assets/tv-ideas.normalized.jsonl \
   content/early_trust.strategy/assets/
EARLY_TRUST_FRAME="2026-06-05..2026-06-12" \
EARLY_TRUST_AUTHORS="<активный_в_июне_автор>" \
npm start -- --backtest --symbol BTCUSDT ./content/early_trust.strategy/early_trust.strategy.ts

# paper (боевой режим проверки):
npm start -- --paper --symbol BTCUSDT ./content/early_trust.strategy/early_trust.strategy.ts --ui
```

Paper-процесс — **только под systemd/cron** (запущенное из VSCode-сессии умирает
вместе с ней) и только с `--ui` (headless умирает, см. уроки OOM-инцидента).

## Контракт фида

Скрейпер (tv-ideas.mjs с правкой `--store`, см.
`agent/notes/tradingview-dataset/session24/tv-ideas.firstseen.mjs`) кроном
раз в 5–10 минут дописывает идеи в стор; фид стратегии — этот же файл или его
нормализованная копия. Поля обязательные: `id, ts(мс), symbol(BTCUSDT-формат),
direction, author, title, url`. `firstSeen` пишется скрейпером и в торговле не
используется — он нужен для последующей сверки «когда идея реально стала видна»
(lagSec) и защиты от удалений.

## Что менять НЕЛЬЗЯ (проверено, ломает сигнал)

- добавлять фильтр по PnL автора (p 0.005 → 0.242);
- добавлять фильтр «не входить, когда шумно» (лифт +1.493 → +1.03);
- менять определение ранности (≤2 чужих / 24 ч — заявленная ячейка контролей);
- «downgrade» списка вручную: убыточные Avramis/Solldy наверху — часть правила.

Ноль сделок неделями — ожидаемое поведение (доверенные молчат), не повод крутить
параметры. Пересмотр — по итогам 2–3 месяцев paper против бэкфил-ожидания.

## Деплой на CT105 (стенд, доступ есть и у Петра)

Расклад: `/data/backtests/_agent/paper/paperhands` — клон ветки
`agent-night-YYYYMMDD`, рабочий каталог `example/`. Один paper-инстанс
(BTCUSDT: у текущих доверенных это самый плотный поток, ~2–3 идеи/мес; порт UI
60050 один на хост, поэтому один процесс). Юниты systemd:

| юнит | что делает |
|---|---|
| `quant-tv-scrape.timer` → `.service` | раз в 10 мин `scripts/scrape-feed.sh`: ленты 2 доверенных → сторы с firstSeen → нормализация в фид |
| `quant-paper-early.service` | `npm start -- --paper --symbol BTCUSDT ./content/early_trust.strategy/early_trust.strategy.ts --ui`, Restart=always |

UI: `http://192.168.1.x(CT105):60050`. Сделки — `dump/` в каталоге стратегии.
Смена месяца: 1-го числа `node scripts/trusted.mjs <datasetContentDir>` (нужен
свежий месячный пакет датасета), рестарт paper-юнита (список читается на старте).
